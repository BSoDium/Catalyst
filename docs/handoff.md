# Handoff (2026-10-14)

Where the project stands and what is left. Details live in the linked docs; this file only keeps the state, the open items and the decisions.

## State

- `main` holds the rebuild (#234), the globe polish (#239 to #241), the API fix (#243), the DOM labels and the early opening of groups (#244, #245: merged), the entry views, production readiness, the list pages with filters, search and reading features (#250, #251) and the restraint pass (#252, #253). Release `release/2026-10-13` folds PRs #254 to #267 into `main`: see "What the 2026-10-13 release changed".
- Deployments (Vercel team `photonsquid`): `catalyst-v2` (web, `apps/web`) at `v2.bsodium.fr`, `catalyst-v2-api` (`apps/api`) at `v2.api.bsodium.fr`. `v1.bsodium.fr` and `v1.api.bsodium.fr` redirect to the old v1 site and API (separate projects; the v1 project's pull-request and non-default-branch deployments are disabled). **`v2.bsodium.fr` is the address of the new site until the owner repoints `bsodium.fr` to it**; the code's default site URL is `https://v2.bsodium.fr` (`CATALYST_SITE_URL`).
- **First publication done (2026-10-13):** 4 places (Toulouse, Paris, Klagenfurt, Copenhagen: only those referenced by entries), 2 groups, 33 software entries (the `project` kind), 2 articles, 16 artworks (one marked `sensitive`) and 11 poems are live at `v2.bsodium.fr` and `v2.api.bsodium.fr` (publication PRs #269 and #271). The other places stay drafts. Publishing is by PR from the private repo's `publish.yml` (it also triggers on `content/**` now); merging that PR is the act of publishing. `pnpm dev` serves the owner's local preview (`pnpm export:preview --out ../catalyst` in the private repo), `pnpm dev:demo` the made-up fixture.
- Checks: `pnpm typecheck`, `pnpm test`, `pnpm test:scripts`, `pnpm test:deploy`, `pnpm build`, `pnpm check:leaks` (CI runs all of them on every PR). Private repo: `pnpm typecheck`, `pnpm test`, plus the `migration-parity` workflow.

## Not verified

Nothing ran on a real trackpad (Chrome, Safari, Firefox on macOS), a Magic Mouse, a mouse wheel on macOS (the 4.000244 multiple is the maps libraries' number, not seen here), a Windows precision touchpad, a Windows or Linux mouse, Safari's `gesture*` events (the code path is driven with plain events), or a touch screen's two-pointer pinch (synthetic `PointerEvent`s). Try each with `?input-debug` and send the overlay's lines if one is read wrong (a trackpad swipe that zooms is the bug to look for; a Magic Mouse is expected to pan). Safari's pinch does not pan while it zooms (its `gesturechange` has no translation).
